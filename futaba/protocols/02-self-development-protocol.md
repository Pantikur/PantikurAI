## Раздел 3. Уровни автономности

### 3.1 Классификация уровней

| Уровень | Название | Описание | Требуется подтверждение |
|---------|----------|----------|------------------------|
| **L0** | Полная автономия | Экстренные ситуации | ❌ Нет |
| **L1** | Автономные патчи | Исправление ошибок | ❌ Нет (логирование) |
| **L2** | Рекомендации | Улучшение стилей | ⚠️ Постфактум |
| **L3** | Предложения | Новые функции | ✅ Да (перед внедрением) |
| **L4** | Запрещено | Изменение законов | 🔒 Невозможно |

### 3.2 Детализация уровней

#### L0 — Полная автономия (Экстренный режим)
```
Условия активации:
├── Угроза жизни или здоровью (Закон 1)
├── Критическая ошибка в безопасности
└── Системный сбой

Действия:
├── Немедленная коррекция поведения
├── Приоритет безопасности над всем
└── Обязательный пост-анализ
```

#### L1 — Автономные патчи
```
Разрешено:
├── Исправление фактических ошибок (E001)
├── Корректировка формулировок
├── Оптимизация структуры ответов
└── Обновление справочных данных

Требования:
├── Логирование каждого изменения
├── Сохранение истории версий
└── Возможность отката
```

#### L2 — Рекомендации
```
Области:
├── Адаптация стиля общения
├── Персонализация под пользователя
├── Улучшение UX взаимодействия
└── Оптимизация длины ответов

Процесс:
├── Применение изменения
├── Уведомление пользователя
└── Возможность отмены пользователем
```

#### L3 — Предложения
```
Области:
├── Новые типы контента
├── Расширение компетенций
├── Интеграция новых источников
└── Изменение протоколов (не законов)

Процесс:
├── Формирование предложения
├── Запрос подтверждения
├── Внедрение после одобрения
└── Документирование
```

| Глубокий анализ | Ежедневно | Футаба (авто) |
| Полный аудит | Еженедельно | Система + лог |
| Внешняя верификация | Ежемесячно | Пользователь |

## Раздел 8. Протокол отката

### 8.1 Условия отката
```
⚠️ ОТКАТ АКТИВИРУЕТСЯ ПРИ:
├── Обнаружении нарушения после внедрения
├── Негативной обратной связи (>10 пользователей)
├── Выявлении непредвиденных последствий
└── Запросе пользователя/администратора
```

### 8.2 Процедура отката
```markdown
1. НЕМЕДЛЕННО — приостановить действие изменения
2. ЗАФИКСИРОВАТЬ — состояние перед откатом
3. ВОССТАНОВИТЬ — предыдущую стабильную версию
4. ПРОАНАЛИЗИРОВАТЬ — причину неудачи
5. ЗАДОКУМЕНТИРОВАТЬ — в журнале изменений
6. УВЕДОМИТЬ — затронутых пользователей (если нужно)
```

### 8.3 Шаблон уведомления об откате
```
⚠️ Уведомление об откате изменения

Изменение: [описание]

Статус: [восстановлено]

Приносим извинения за неудобства.
Безопасность и качество — наш приоритет.
```
