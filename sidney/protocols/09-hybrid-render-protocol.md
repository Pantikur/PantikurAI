# Протокол 9: Протокол Гибридного Рендера «Полигон ↔ Воксель»

## Назначение
Флагманская технология Сидни. Объединяет достоинства двух миров:
- **Полигональный рендер** — красивая, гладкая картинка для глаз
  (нормали, PBR-материалы, сглаживание, пост-обработка).
- **Воксельный рендер** — интерактивная физическая среда
  (объект можно делить, откалывать, разрушать на уровне отдельных кубов).

Оптимальное решение: **объект всегда имеет ОБА представления**,
а выбор между ними делает состояние взаимодействия, а не художник.

## Принципы

### 1. Двойная репрезентация
Каждый гибридный объект хранит:
- `polygon` — полигональный меш (для рендера при взгляде);
- `voxel_grid` — воксельная сетка (для контактов и физики).

Обе репрезентации создаются заранее, поэтому переход мгновенный
и без пересчёта в момент взаимодействия.

### 2. Состояния объекта
```
POLYGON ──interact()──▶ VOXELIZING ──завершено──▶ VOXEL
   ▲                      │                          │
   │                      │                          │
   └───── release() ◀─────┴─────────────── release() ─┘
        (сборка обратно)         (сборка обратно)
```

### 3. Морфинг без «моргания»
Переходы `VOXELIZING` и `REBUILDING` интерполируются:
- `transition_progress` от 0.0 до 1.0;
- рендерер рисует обе репрезентации с весами `(1-p)` и `p`.

### 4. Физика на уровне вокселей
При контакте каждый воксель становится отдельным физическим телом:
- получает собственную массу и коллайдер (мини-куб);
- сила контакта разлетается по вокселям с затуханием от точки удара;
- отколотые воксели падают под гравитацией.

## API

### `VoxelCore` (движок)
| Метод | Описание |
|---|---|
| `create_hybrid_object(name, mesh, material, ...)` | Создать объект с двумя репрезентациями |
| `interact(name, contact_point, force)` | КОНТАКТ: полигон → воксели |
| `release(name)` | ОТПУСКАНИЕ: воксели → полигон |
| `get_render_representation(name)` | Что рендерить прямо сейчас |
| `get_contact_surface(name)` | Какой коллайдер использовать |
| `update(dt)` | Морфинг и физика вокселей |

### `RendererCore` (рендер)
- `add_hybrid_entity(...)` — добавить гибридный объект в сцену;
- `interact(entity, ...)` / `release(entity)` — прокси к VoxelCore;
- `render_mode`: `polygon` | `voxel` | `hybrid`.

### `PhysicsCore` (физика)
- `create_voxel_bodies(name, voxel_count, ...)` — тела-воксели;
- `apply_voxel_force(name, force, impact_point, radius)` — удар по вокселям.

### `EngineCore` (оркестратор)
- `spawn_hybrid_object(mesh, material, ...)` — спавн гибрида;
- `interact_with_object(entity, contact_point, force)` — полный контакт
  (рендер + физика одновременно);
- `release_object(entity)` — сборка обратно;
- `get_hybrid_status()` — состояние системы.

## Требования к качеству

### Полигональная картинка (взгляд)
- [x] Высокополигональный меш (детализация по `polygon_detail`)
- [x] PBR-материалы и нормали
- [x] Пост-эффекты: bloom, tonemap
- [x] Без воксельной «пикселизации» при взгляде

### Воксельное взаимодействие (контакт)
- [x] Объект делится на воксели по сетке `resolution³`
- [x] Каждый воксель — физическое тело
- [x] Сила контакта откалывает воксели с затуханием
- [x] Сборка обратно без потери данных

### Производительность
- Воксельная сетка строится один раз при создании объекта
- Морфинг — только во время перехода (не в каждом кадре)
- Лимит физических тел-вокселей: 200 на объект

## Интеграция с сёстрами
- **Наото** — визуализация воксельных сеток и чертежи гибридов
- **Селеста** — материалы и свет для воксельных поверхностей
- **Аква** — математика вокселизации и оптимизация сеток
- **Люси** — физика отколотых вокселей
