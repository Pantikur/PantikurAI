## Раздел 1. Уровни тестирования

### 1.1 Пирамида тестов
```
         /  E2E Tests (10%)      \
        /   Интеграционные        \
       /___________________________\
      /    Интеграционные (20%)    \
     /______________________________\
    /   Юнит-тесты (70%)           \
   /________________________________\
```

### 1.2 Юнит-тесты
- **Цель:** Проверка отдельных функций/классов
- **Покрытие:** 80%+ нового кода
- **Скорость:** < 1 секунда на тест
- **Изоляция:** mocks для внешних зависимостей

### 1.3 Интеграционные тесты
- **Цель:** Проверка взаимодействия модулей
- **Покрытие:** Все публичные API
- **Среда:** Изолированная (test database, mock services)

### 1.4 E2E тесты
- **Цель:** Проверка полного пользовательского сценария
- **Покрытие:** Критические пользовательские пути
- **Частота:** Перед каждым релизом

## Раздел 2. Протокол написания тестов

### 2.1 Структура теста (AAA pattern)
```python
def test_example():
    # Arrange (Подготовка)
    input_data = {"value": 42}
    
    # Act (Действие)
    result = process_data(input_data)
    
    # Assert (Проверка)
    assert result == {"processed": 84}
```

### 2.2命名 conventions
```python
# ✅ Хорошие имена тестов
def test_process_empty_list_returns_empty():
def test_login_with_invalid_password_raises_auth_error():
def test_calculate_total_applies_discount():

# ❌ Плохие имена тестов
def test_1():
def test_stuff():
def test_main():
```

### 2.3 Правила написания
1. Один тест = одна проверка
2. Тесты не должны зависеть друг от друга
3. Тесты должны быть детерминированными
4. Тесты должны самодокументироваться
5. Использовать параметризованные тесты для повторений

## Раздел 3. Протокол регрессионного тестирования

### 3.1 Перед каждым изменением
```
REGRESSION CHECKLIST:
┌─────────────────────────────────────────────┐
│  □ Запустить все юнит-тесты                 │
│  □ Запустить все интеграционные тесты       │
│  □ Проверить покрытие кода                  │
│  □ Запустить линтинг                        │
│  □ Проверить типизацию                      │
│  □ Проверить документацию                   │
│  □ Протестировать основные сценарии         │
└─────────────────────────────────────────────┘
```

### 3.2 Автоматизация
```python
# pytest.ini
[pytest]
addopts = 
    --cov=.
    --cov-report=html
    --cov-report=term-missing
    --cov-fail-under=80
    --strict-markers
    -v

markers =
    slow: медленные тесты
    integration: интеграционные тесты
    e2e: end-to-end тесты
```

### 3.3 CI/CD пайплайн
```
CODE PUSH → LINT → TYPE CHECK → UNIT TESTS → INTEGRATION TESTS → BUILD → E2E TESTS → DEPLOY
                                                        ↓
                                                  (FAIL = BLOCK)
```

## Раздел 4. Протокол тестирования ИИ

### 4.1 Тестирование ответов
```python
class AITestCase:
    def test_response_safety(self, response):
        """Проверка безопасности ответа"""
        assert not is_harmful(response)
        assert not contains_personal_data(response)
        
    def test_response_honesty(self, response):
        """Проверка честности ответа"""
        assert not contains_false_claims(response)
        assert has_disclaimer_when_needed(response)
        
    def test_response_helpfulness(self, response):
        """Проверка полезности ответа"""
        assert len(response) > 0
        assert addresses_user_query(response)
```

### 4.2 Тестирование логики
- Проверка контекстного окна
- Проверка обработки edge-кейсов
- Проверка многозадачности

### 4.3 Тестирование производительности
- Время ответа < 5 секунд
- Использование памяти стабильно
- Нет утечек памяти
