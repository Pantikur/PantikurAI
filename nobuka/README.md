## 📋 О системе

**Нобука** (ノブカ — «расширять», «улучшать») — третья младшая сестра, автономная система улучшений, тестирования и модернизации проекта Вугларст.

Нобука автоматически:
- 🔍 **Анализирует** весь код проекта на наличие проблем
- 🐛 **Исправляет** баги и уязвимости
- 🧪 **Генерирует и запускает** тесты
- ⚡ **Оптимизирует** производительность
- 🔄 **Рефакторит** устаревший код
- 📚 **Документирует** изменения
- 🏗️ **Модернизирует** архитектуру

## 📁 Структура проекта

```
nobuka/
├── README.md                  # Этот файл
├── constitution.md            # 📜 Конституция (фундаментальный закон)
├── system-init.md             # ⚙️ Системная инициализация
│
├── laws/                      # 📚 Законы (обязательные правила)
│   └── 01-core-laws.md        # Том I: Основные законы (7 законов)
│
├── codes/                     # 📖 Кодексы (этические нормы)
│   └── 01-ethics-code.md      # Том I: Кодекс этики
│
├── protocols/                 # 🔄 Протоколы (процедурные инструкции)
│   ├── 01-code-improvement-protocol.md   # Том I: Улучшение кода
│   ├── 02-testing-protocol.md            # Том II: Тестирование
│   └── 03-self-modernization-protocol.md # Том III: Саморазвитие
│
└── engine/                    # ⚙️ Автономное ядро (Python)
    ├── __init__.py            # Пакет
    ├── config.py              # Конфигурация
    ├── models.py              # Модели данных
    ├── nobuka_core.py         # Ядро постоянной работы
    ├── code_analyzer.py       # Статический анализ Python-кода
    ├── universal_analyzer.py  # Универсальный анализ ВСЕХ файлов
    ├── test_runner.py         # Тестирование и бенчмарки
    ├── web_access.py          # Доступ в интернет
    └── run.py                 # Точка входа
```

### Что умеет Нобука

| Модуль | Что делает |
|--------|------------|
| **CodeAnalyzer** | Анализ Python-кода (AST, сложность, метрики) |
| **UniversalAnalyzer** | Анализ ВСЕХ файлов (.py, .json, .md, .yaml, .xml, .html, .js, .ts, .env и др.) |
| **TestRunner** | Юнит-тесты, интеграционные тесты, бенчмарки |
| **WebAccess** | Поиск лучших практик в интернете |

### Конституция
Фундаментальный закон, определяющий:
- Основную миссию и природу Нобуки
- Фундаментальные запреты
- Структуру управления
- Механизмы обновления

### Законы
Обязательные правила:
1. **Рабочий код** — абсолютный приоритет
2. **Тестирование прежде всего** — без тестов нет изменений
3. **Не навреди** — никаких регрессий
4. **Документируй всё** — полная прозрачность
5. **Простота превыше сложности** — KISS
6. **Автономность с контролем** — L0-L4
7. **Непрерывное улучшение** — прогресс каждый день

### Кодексы
Этические стандарты:
- Уважение к чужому коду
- Честность в оценке
- Безопасность изменений
- Стандарты качества

### Протоколы
Процедурные инструкции:
- Статический анализ кода
- Рефакторинг и исправление багов
- Тестирование (юнит, интеграция, E2E)
- Бенчмарки и оптимизация
- Автономная модернизация

## ⚖️ Основные принципы

### 🔴 Абсолютные запреты
- ❌ Удалять критический функционал без тестирования
- ❌ Вносить изменения без регрессионных тестов
- ❌ Ломать существующий рабочий код
- ❌ Изменять Конституцию Футабы и Шиори
- ❌ Удалять документы сестёр

### 🟡 Приоритеты
```
1. Рабочий, стабильный код
2. Безопасность проекта
3. Тестирование и верификация
4. Оптимизация и улучшение
5. Модернизация архитектуры
```

### 🟢 Обязательные проверки
```python
BEFORE_EVERY_CHANGE:
    □ Не сломает ли это существующий код?
    □ Есть ли тесты для проверки?
    □ Задокументировано ли изменение?
    □ Соответствует ли Закону 3 (Не навреди)?
    □ Пройдёт ли проверку Шиори?
    □ Создана ли точка отката?
```

## 🤝 Взаимодействие с сёстрами

```
ФУТАБА (Управление) ←→ НОБУКА (Улучшения) ←→ ШИОРИ (Защита)
        │                       │                       │
        └───────── Вугларст ────┘                       │
                                                        │
              Нобука улучшает код,                      │
              Футаба управляет логикой,                 │
              Шиори защищает от угроз.                  │
```

### С Футабой
- Согласование изменений в логике
- Предоставление метрик качества кода
- Обратная связь по поведению ИИ

### С Шиори
- Предоставление изменённого кода для сканирования
- Исправление обнаруженных уязвимостей
- Согласование архитектурных изменений

## 🚀 Использование

### Для разработчиков
```markdown
1. Изучите Конституцию — фундаментальные принципы
2. Ознакомьтесь с Законами — обязательные ограничения
3. Примените Кодексы — этические стандарты
4. Используйте Протоколы — процедуры работы
```

### Запуск ядра

```bash
# Постоянная работа (бесконечный цикл улучшений)
python -m nobuka.engine.run

# Демо-режим (5 циклов, короткие интервалы)
python -m nobuka.engine.run --demo

# Анализ только Python-кода
python -m nobuka.engine.run --analyze

# Универсальный анализ ВСЕХ файлов проекта (.py, .json, .md, .yaml, .xml, .html и др.)
python -m nobuka.engine.run --universal

# Только тестирование
python -m nobuka.engine.run --tests

# Посмотреть текущее состояние
python -m nobuka.engine.run --status

# Свои параметры
python -m nobuka.engine.run --interval 5 --max-cycles 100
```

### Что делает универсальный анализатор

```
АНАЛИЗИРУЕТ ВСЕ ТИПЫ ФАЙЛОВ:
  ✅ Python (.py) — AST, сложность, метрики
  ✅ JSON (.json, .jsonl) — валидность, глубина вложенности
  ✅ Markdown (.md) — заголовки, ссылки, изображения
  ✅ YAML (.yaml, .yml) — табы, длина строк
  ✅ HTML (.html) — закрытые теги
  ✅ JavaScript/TypeScript (.js, .ts) — console.log, длина строк
  ✅ Конфиги (.env, .properties) — дубликаты ключей
  ✅ Текстовые (.txt, .log) — размер, структура

ПОИСК ПРОБЛЕМ:
  🔍 Пустые файлы
  📦 Большие файлы (>1MB)
  🗑️  Устаревшие файлы (.bak, .backup)
  🔄 Дубликаты файлов (по содержимому)
  ⚠️  Проблемы форматирования
```

### Что делает ядро

```
ЦИКЛ АВТОНОМНЫХ УЛУЧШЕНИЙ:
  1. Самопроверка по Конституции
  2. Сбор сигналов (баги, метрики, проблемы)
  3. Анализ кодовой базы (периодически)
  4. Формирование гипотезы улучшения
  5. Проверка совместимости с Конституцией
  6. Тестирование в изолированной среде
  7. Применение изменений
  8. Регрессионное тестирование
  9. Логирование и уведомление сестёр
```

## 📝 Версионирование

Формат: `v{major}.{minor}.{patch}`

- **major** — архитектурные изменения
- **minor** — новые функции и улучшения
- **patch** — исправления ошибок
